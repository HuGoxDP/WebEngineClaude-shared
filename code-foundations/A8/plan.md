# A8 — the editor takes the new engine (plan)

Standard gate (Sonnet task). Source: `tasks/A8-editor-new-engine.md` + `code-foundations/A8/research.md`.
Branches: `A8-editor-new-engine` in WebEngineTSEditor (build) and .claude-shared (claim/roadmap/notes).
The engine repo gets no branch of this task: the pack is made by hand from the engine worktree at
fresh `origin/master` and lands in the editor's tarball + lockfile.

## Phase 1 — pack the engine into the editor (build)
- `File scope`: `WebEngineTSEditor/app/WebEngineTS-0.1.0.tgz`, `WebEngineTSEditor/app/package-lock.json`
- Steps: in the engine worktree `npm run build`; stamp `0.1.0-local.<ts>`; `npm pack`; restore
  `package.json`; rename to `WebEngineTS-0.1.0.tgz`; copy into `app/`; `cd app && npm install
  ./WebEngineTS-0.1.0.tgz` (with `npm ci` first so the lockfile is the committed one).
- Commit on the editor branch: `build(app): take the engine with the version-2 reader`
  (tarball + lockfile together, per the card).
- Done when: `require("WebEngineTS")` in `app` resolves the new stamp
  (`BuildInfo.version`) and `npx tsc` still sees the A4 API.

## Phase 2 — open scenes through the version check (feat)
- `File scope`: `WebEngineTSEditor/app/src/app/services/commands.service.ts`,
  `WebEngineTSEditor/app/src/app/i18n/en.ts`, `WebEngineTSEditor/app/src/app/i18n/uk.ts`
- Depends on: Phase 1.
- `_loadSceneText`: replace `data.version !== 1` with the engine's API — unreadable/newer than
  `readableVersions` (`versionOf`, `canRead`) or `UnsupportedFormatError` → the new
  `scene.tooNew` message; a malformed scene keeps `scene.parseFailed` / `scene.invalid`
  (`!Array.isArray(data.roots)` etc. stays for the shape check). On refusal nothing changes:
  selection, history and the current scene stay (the existing `fail()` path already returns false
  before touching state — verify by test).
- New i18n key `scene.tooNew` in en + uk, same tone as `scene.invalid`, naming the file, its
  version, the versions this editor reads, and "update the editor".
- Acceptance: `grep -n "version !== 1" app/src` returns nothing.

## Phase 3 — e2e scenarios for the readers (test)
- `File scope`: `WebEngineTSEditor/app/e2e/**`
- Depends on: Phase 2.
- Fixtures under `app/e2e/fixtures/` (committed JSON): v1 scene; a scene with no `version`;
  a v2 scene (generated by the new engine in link mode from a small Node script under
  `app/e2e/fixtures/`); a v3 scene; garbage. Each refusal scenario asserts the previous scene
  is still shown afterwards.

## Phase 4 — docs (docs, Minimal)
- `File scope`: `WebEngineTSEditor/README.md`, `WebEngineTSEditor/docs/**`
- Depends on: none (files disjoint from Phases 1-3 except the editor root README, which the
  pack phase does not touch).
- Any doc mentioning the literal version check / the engine stamp gets the new wording.

## Phase 5 — full checks (Standard)
- `File scope`: none (commands only)
- Depends on: Phases 1-4.
- `cd app && npm ci` from the committed lockfile (tarball integrity must match), `npx ng build`,
  then `npm run e2e` **inside `editor-e2e.lock`** with `E2E_PLAYWRIGHT_DIR` and
  `E2E_BROWSER_CHANNEL` per the research decisions. Report: engine stamp, e2e counts
  before/after (baseline on master: run the e2e once on the old tarball before the pack),
  any engine drift that needed an editor change, anything reported instead of patched.
- Before the merge (inside `merge.lock`): re-sync the editor branch with `origin/master` (the
  editor repo's own default) and check whether the **engine repo's** master moved since the
  pack; if it did, repeat Phase 1 and re-run Phase 5.
