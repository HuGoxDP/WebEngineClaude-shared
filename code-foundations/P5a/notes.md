## The run of the restore procedure (docs/backup-restore.md, verbatim)

Scratch stack (`-p vlabscratch`, scratch volumes, port 3998, built from this branch):

1. Seeded: one row (`insert into scenarios … 'backup-proof'`) and one archive object
   (`printf "restore-me" > /v/objects/backup-proof.txt`, sha256
   `f020ee6da0776ba3b741b888787532a4cb1f3cff4975f7e29891cba35571f3ad`).
2. `backup.mjs` once: `db.sql.gz` 3512 bytes + four volume tars + manifest, 0.7 s.
3. `down -v` — the row count went to 0 and the object was gone (the disaster).
4. Fresh `up`, `restore.mjs` **dry run first** (printed what it would do), then `--yes`:
   `database restored into virtual_lab@database`, all four volumes restored.
5. Verified: `select count(*) where id='backup-proof'` → **1**; the object read back with the
   **same sha256**; `curl -kfsS https://127.0.0.1:3998/scenarios/backup-proof.txt` →
   **restore-me** (nginx serves the restored bytes).
6. Regression check for the partial-directory fix: a run with `DB_HOST=nosuchhost` failed loudly
   and left **no** new directory under the backup root.

## HTTPS proof (local)

`curl -k https://127.0.0.1:3998/` → 200 with `Strict-Transport-Security: max-age=31536000` and the
CSP; the same container over plain http has **no** HSTS (the map's empty value is dropped);
`/api/health` answers 200 over TLS; the served certificate carries SANs
`DNS:localhost, IP:127.0.0.1` (self-signed, generated by the image build).

## Failures found and fixed during the run (each pinned)

- the `.env.example` comment line (compose env parse error) — fixed, `eb7d00c`;
- a failed backup left a manifest-less directory — fixed + verified by run 6 above;
- the restore needs write mounts while the nightly job must not have them — the restore override;
- the scratch stack's port borrowed `FRONTEND_PORT` (two containers cannot publish one port) —
  `SCRATCH_FRONTEND_PORT`;
- HSTS set at server level never reached the page — moved into `csp.conf`;
- `node:20-alpine` has no `openssl` — installed in the build stage;
- the first draft of the doc's commands missed the `-f` files, which makes compose pick the main
  compose file (and so the live stack's container and volume names) — every command carries them.

## Deviations

- The plan's HTTPS phase said "new file only": `listen 443 ssl` cannot be added from inside a
  server block, so `nginx.conf` and `Dockerfile.frontend` carry the listener and the
  certificate. Recorded in the commit messages.
- The restore procedure is a *scratch stack* run (own volumes/names/ports), not the live stack,
  exactly as the row asks ("a restore actually tried on the local stack" = a local scratch copy,
  documented, output pasted above).
